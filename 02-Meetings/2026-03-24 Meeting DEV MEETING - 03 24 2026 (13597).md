    *   Se discutió la extracción de datos desde Google Ads sin incluir reportes complejos en la fase inicial; la idea era almacenar la data en documentos (por ejemplo, Google Sheets) para luego analizarla más a fondo.

    *   Se confirmó que la fase 1 se considera suficiente para comenzar y se procedió a evaluar instrucciones para ejecutar la extracción.

*   **Integración y diferencias entre Cloud Code y Open Cloud** Actualización
    *   Se detallaron las características y diferencia entre Cloud Code y Open Cloud, destacando que Cloud Code se utiliza para ejecuciones locales mediante scripts y Open Cloud es una aplicación con servidor virtual, permitiendo conexiones con APIs de manera más amigable.
    *   Cristian Berrío mencionó aspectos técnicos como el manejo de memoria, consumo de tokens y tiempos de ejecución, haciendo énfasis en la importancia de mantener la información en repositorios y archivos (por ejemplo, archivos MD).
    *   La discusión abordó la necesidad de optimizar las tareas, utilizando herramientas ya instaladas (como el 'playrate' para scrapear páginas) y de aprovechar las extensiones para facilitar la ejecución desde dispositivos móviles.

*   **Automatización y creación de currículos automatizados** Idea
    *   Se propuso desarrollar una 'skill' o agente especializado que construya currículos (por ejemplo, para voleibol) integrando datos históricos, libros, currículos previos y estructuras preestablecidas de prácticas.
    *   Trellis Fields enfatizó la necesidad de que, al modificar la información, la herramienta sea capaz de actualizar las páginas de Notion de forma automática, y sugirió utilizar un modelo GPT avanzado a futuro, dado que Cloud Code podría resultar costoso por el consumo intensivo de tokens.
    *   Se analizó la posibilidad de combinar datos de distintos orígenes para estructurar el currículum, resaltando el valor de automatizar este proceso.

*   **Sincronización de repositorios y uso de GitHub/Dispatch** Decisión
    *   Se resaltó la importancia de mantener un repositorio centralizado para compartir y actualizar el código y las 'skills' de manera colaborativa.
    *   Se discutió el uso de comandos y herramientas como GitHub y Dispatch para automatizar el 'push' al repositorio y facilitar la sincronización entre distintos dispositivos y miembros del equipo.
    *   La idea es reducir procesos manuales y permitir actualizaciones desde dispositivos móviles, asegurando que el equipo completo tenga acceso a los últimos cambios.

*   **Problemas de acceso y consumo en integración de herramientas** Problema
    *   Se identificaron bloqueos en la integración, por ejemplo, que el bot no puede acceder a páginas privadas de Notion debido a restricciones de permisos (captcha, páginas protegidas, etc.).
    *   Se discutieron preocupaciones sobre el coste asociado al consumo de tokens y el tiempo de ejecución, especialmente en tareas que involucren gran cantidad de datos (como currículos extensos).

*   **Configuración y evaluación de herramientas adicionales (Cursor, Whisper y extensión Cloud Code)** Actualización
    *   Se analizó la instalación y configuración de herramientas auxiliares como Cursor para gestionar repositorios locales y sincronización de archivos.

    *   Cristian Berrío y Trellis Fields revisaron comandos y la utilización de extensiones que hagan la interacción con Cloud Code más intuitiva y eficiente.
