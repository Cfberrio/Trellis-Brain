**Veredicto: NO se puede "coger el repo y montarlo en Lovable".**

Tu frontend es **Next.js 16 (App Router)**. Lovable solo edita proyectos **Vite + React** (o el nuevo TanStack Start). Importar un repo Next.js App Router → Lovable **no lo puede editar**. No es lift-and-shift, es **rebuild**.
Primero, confirmo qué tienes ("Bursle" = **Vercel**, por `vercel.json` + `@vercel/analytics` + `botid`):

**Lo que tienes hoy**

| Pieza | Detalle |
| ---| --- |
| Framework | Next.js 16 App Router, React 19, TS, Tailwind 3, shadcn/Radix |
| Host | Vercel (`vercel.json`, cron diario, headers, botid) |
| Backend API | ~50 API routes server-side (`app/api/**/route.ts`) |
| Pagos | Stripe (checkout sessions, payment intents) |
| Email | Resend + nodemailer (campañas, recordatorios) |
| Cron | Vercel cron (`/api/cron/...` 23:00) + `node-cron` + scripts `tsx` |
| DB/Auth/Storage | Supabase (`tdyyjoyotvzgbeowtlfv`) |
| Dashboards | admin, dashboard (pagos, schedule, messages, players, coupons, skills) |

App grande y madura. No prototipo.

**Por qué Lovable no traga esto**

Docs + guías de import confirman requisitos de Lovable:
*   Solo **Vite + React/TS** (o TanStack Start). **Next.js App Router explícitamente NO soportado.**
*   Un solo `package.json` raíz, sin monorepo, Tailwind v3/v4, dev script que arranca, **sin webpack custom**.
*   Cita textual: _"If your repo is a Next.js Pages Router app... don't import — Lovable cannot productively edit"_.
*   Recomendación oficial para stacks no soportados: _"use Lovable to generate a fresh frontend and connect it to your existing backend"_ → o sea, **rehacer el front desde cero**.
Mismatch duro:

| Tu pieza | Lovable | Resultado |
| ---| ---| --- |
| Next App Router + Server Components | Vite SPA | Reescribir todo el front |
| ~50 Next API routes (Node) | Edge Functions Deno | Reescribir cada una |
| Vercel cron | Supabase cron (pg\_cron) | Reconfigurar |
| `node-cron`, scripts `tsx`, nodemailer | Deno runtime | No corren, reescribir |
| botid, `@vercel/analytics`, next/image | No existen en Lovable | Quitar/reemplazar |

**Lo único migrable "directo"**

**Supabase → Lovable Cloud**: Lovable Cloud ES Supabase gestionado. Mover schema, RLS, storage, edge functions y datos es factible (hay tooling). Pero ojo: Lovable Cloud es Supabase _con menos control directo_. Y la pregunta de "todo en un lugar" choca: Lovable Cloud te da menos acceso al dashboard de Supabase puro.

**Opciones reales**

**A. Rebuild completo en Lovable** (lo que pides literal)
*   Regenerar front en Vite+React, portar ~50 routes a edge functions Deno, Supabase→Lovable Cloud.
*   Esfuerzo: **semanas-meses**. Riesgo alto: SEO (Next SSR/sitemap/rewrites se pierden), pagos, emails, crons — todo a revalidar.
*   Veredicto: **caro y arriesgado. No lo recomiendo para una app en producción.**
**B. Híbrido** (lo más sensato si quieres Lovable)
*   Quedarte en Next.js/Vercel. Usar Lovable solo para construir **piezas nuevas de UI** y conectarlas a tu Supabase vía REST.
*   No consolida "todo en un lugar", pero cero riesgo a lo existente.
**C. No migrar** — consolidar de otra forma
*   Si el objetivo real es "todo en un lugar / menos herramientas": ya estás casi consolidado. Vercel (host+cron) + Supabase (DB/auth/storage). Eso son **2 servicios**, estándar y sólido. Lovable no reduce eso, lo cambia por una caja con menos control.

**Mi opinión**

"Todo a Lovable Cloud" suena a un servicio menos, pero técnicamente es **reescribir una app de producción entera** para encajar en una herramienta pensada para prototipos Vite, perdiendo Next.js SSR/SEO y el control directo de Supabase. **Mala relación riesgo/beneficio.** Si quieres usar Lovable, opción **B**.
