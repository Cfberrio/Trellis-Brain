**Diagnosis (confirmed by docs)**

*   **Calendar-native notifications fire for EVERY appointment in calendar. No source filter exists.** You can toggle by _type_ (confirm/reminder/follow-up) but NOT by "came from widget vs API." So while tour emails live in calendar settings, real bookings always get caught. ([notifications doc](https://help.gohighlevel.com/support/solutions/articles/155000003441-calendar-email-in-app-sms-whatsapp-appointment-notifications))
*   **Workflows CAN filter by source.** Appointment trigger has `Modified By` filter: **API / Customer / User / Workflow**, plus `In Calendar`. ([appointment status trigger](https://help.gohighlevel.com/support/solutions/articles/155000002619-workflow-trigger-appointment-status))
    *   Widget booking (tour) = **Customer**
    *   Private-integration/API booking (real booking) = **API**
That split is your workaround.

**Fix A — fastest, keeps same calendar (recommended)**

No code change. Keeps shared availability you want.
1. Calendar → **Settings → Notifications** → turn **OFF** native confirmation + reminders + follow-ups (the tour emails).
2. Rebuild those tour emails as a **Workflow**:
    *   Trigger: **Customer Booked Appointment** (or Appointment Status)
    *   Filter `In Calendar` = your booking/tour calendar
    *   Filter **`Modified By`** **= Customer**
3. Result: only widget tours match → tour comms. API bookings = `Modified By: API` → excluded. Real bookings stop getting tour emails.
Want real bookings to get THEIR own comms? Second workflow, same calendar, `Modified By = API` → booking emails.

**Fix B — cleaner structure, more work**

Split into **2 calendars** (Tour vs Booking), point API private-integration at Booking calendar. Stop double-booking by attaching **same shared Schedule** to both (or same assigned user + conflict-calendar check) → availability stays linked. ([Schedules](https://help.gohighlevel.com/support/solutions/articles/155000006215-schedules-centralized-availability-management), [Linked/Conflict calendars](https://help.gohighlevel.com/support/solutions/articles/155000002374-setting-up-linked-calendars-conflict-calendars)). Each calendar keeps own native notifications. Requires changing calendar ID in your edge function.
