## Category definition

**Reliable Venues = venue revenue operators.**

We **install and operate revenue layers** that move a venue from **inquiry → instant response → follow-up → deposit → booked calendar**, so bookings don't depend on the owner or a fragile staff member.

## What we are NOT (anti-price-shopping)

- Not a marketing agency
- Not a software vendor
- Not a "consultant with ideas"
- Not a staffing replacement company
- **We are the operator for the revenue path.**

## 1-liner (default)

**We install and operate the revenue layer that turns venue inquiries into deposits and booked dates—then we get paid on the revenue we unlock.**

## Website headline options

1. **The Revenue Operator for Event Venues**
2. Install the Inquiry-to-Deposit system. Book more dates. Reduce owner dependency.
3. **From Inquiries to Deposits—Automatically**
4. We run the booking pipeline so your calendar fills without extra staff.
5. **A Booked Calendar Is a System**
6. We install and operate the system that produces bookings on purpose.

## Subheadline options

- Instant response + automated follow-up + deposit automation inside one pipeline.
- Centralized booking operations that increase bookings and reduce labor drag.
- We fix the leaks in your booking flow and keep it running.

## "What we do" bullets

- Centralize all inquiries into one pipeline (single source of truth)
- Deploy 24/7 inquiry response + qualification
- Run follow-up until tour/deposit happens
- Automate deposits and booking steps
- Track baseline vs current performance and optimize weekly

## The "umbrella solution" sentence (prevents carving)

**We don't sell pieces. We run the system end-to-end because the outcome only happens when the entire revenue path is operated as one layer.**

## Sales call opener (10 seconds)

> "We're venue revenue operators—we install and run the inquiry-to-deposit layer so bookings happen without you chasing leads or hiring more staff."

## Cold qualifying question (fast filter)

> "Do you have open dates to fill, and is your inquiry-to-deposit process tracked end-to-end in one place?"

## Proof framing (what we measure, always)

- First response time
- Follow-up coverage (attempts per inquiry)
- Deposit rate
- Booked revenue vs baseline
- Utilization (dead dates filled)

## Internal doctrine (team alignment)

- Sell **operation + outcomes**, not tools.
- Require control of the revenue path (pipeline + tracking + compliance).
- If they want more revenue, they must allow the minimum demand layer (or prove demand is already reliable).
- Every conversation returns to: **leaks → system → baseline → uplift**.

## One-line model (working name)

> Temporary product name: **TRELLIS FOR VENUES**

We help underutilized event venues increase monthly profit and bookings via a done-for-you ops system using AI that converts **inquiries → instant response → follow-up → deposit → booked calendar** (with unified CRM/workflows), paid via revshare on **incremental booked revenue above a baseline** (optional retainer add-on).

## Optional dual-model split (if forced)

### Model A — Revenue operator (revshare)
We help underutilized venues get more deposits + booked events via DFY inquiry→deposit automation; paid on incremental booked revenue above baseline.

### Model B — Systems operator (fixed/minimum + optional performance)
We help already-busy venues reduce booking labor + leakage via CRM/workflow consolidation and automation; paid via monthly minimum (and/or performance add-on where measurable).

> If keeping one model, the recommended line above already captures both: profit outcome + systems mechanism + revshare economics.
