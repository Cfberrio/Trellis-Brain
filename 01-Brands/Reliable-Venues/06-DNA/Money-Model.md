## Frameworks in play

- **Money Model stages:** Attraction (get cash) → Upsell / Downsell (get more cash) → Continuity (get the most cash).
- **"Two ways to say yes":** downsells + terms so "no" doesn't mean "lost."
- **Trial With Penalty:** free / low-friction start, but only free if they do the actions that make them a great customer.
- **Menu close / minimum package:** require the minimum bundle so outcomes are controllable + we don't get carved up.
- **Pricing separation:** one-time value vs ongoing value; bill less frequently to reduce churn; show smaller price units, bill longer cycles.
- **Value levers:** increase likelihood (proof + clear milestones) and reduce time / effort (DFY ops).

## Operating rules

- Only promise outcomes we control. If demand is required, the minimum demand layer is required (or they're not a fit).
- Every offer must have: eligibility trigger, upgrade rule, success milestone, next CTA (system runs without improvisation).
- "Free month" is never unconditional — Trial With Penalty tied to exact actions needed for success.
- Money is captured on the same metric we optimize (**incremental booked revenue above baseline**). Ops + reporting built around that metric.
- Continuity is not "support" — it's ongoing outcomes + ongoing reporting + ongoing optimization tied to billing cycle.

## Definitions

- **Baseline:** trailing 60–90-day average monthly booked revenue pre-go-live, verified via deposits / bookings records.
- **Incremental booked revenue:** (current month booked revenue) − (baseline).
- **Total take rate:** Operator % (by stage) + Demand tier % (required minimum).
- **Billing:** monthly in arrears default; upgrade billing starts next billing cycle after acceptance.

## Offer Ladder

### Step 1 — Entry / Acquisition Offer

**Offer name:** Venue Scaling Roadmap + Booking Leak Baseline Audit

- **Price / terms:** $0 to book; requires data submission to keep slot (or $250–$500 refundable "show-up + data submitted" deposit).
- **Trigger:** Books roadmap call AND submits baseline inputs (last 60–90 days booked revenue, inquiry sources, response process, deposit process).
- **Upgrade rule:** Completes call + qualifies as Stage 1–4 (demand exists + open dates + decision maker + will centralize pipeline).
- **Value delivered:** Stage diagnosis + quantified leak map + baseline measurement + 90-day install plan.
- **Next CTA:** Start 30-Day Install Month (Trial With Penalty).

### Step 2 — Core Offer (main profit center)

**Offer name:** Trellis Revenue Operator (BookingOS + Foundation DemandOS)

- **Month 1:** $0 "Install Month" (Trial With Penalty).
- **Month 2+:** Revshare on incremental booked revenue above baseline (Operator % by stage from [[01-Brands/Reliable-Venues/06-DNA/Offer|Offer]]) + Foundation DemandOS +5%.

**Trial With Penalty — Install Month terms:**
- Provide access to calendar, inquiry inboxes, phone / SMS / email, payment / deposit process.
- Route all new inquiries into pipeline.
- Use booking flow as instructed (no parallel shadow process).
- Penalty: if requirements unmet, Install Month converts to fixed setup fee or month-one minimum + we can exit.

**Install Month "Done" milestones:**
- One pipeline live
- AI first response live
- Follow-up sequences live
- Deposit workflow live
- Baseline dashboard live

**60–90-day "Done":**
- Incremental booked revenue above baseline (or agreed performance metric).

### Step 3 — Upsells

| Upsell | Trigger | Pricing | Acceptance moment |
|---|---|---|---|
| **Growth DemandOS** | Foundation live + stable, more volume needed | +8% total (or +3% on top of Foundation) | Day 30 review |
| **Dominate DemandOS** | Aggressive growth / dead-date filling | +10% total (or +5% on top of Foundation) | Day 30 or capacity-constraint moment |
| **Revenue Optimization (Stage 3+)** | Booking consistent, constraint = margin / value per date | +2–4% incremental OR fixed monthly + performance kicker | Quarterly review |
| **Portfolio Operator (enterprise)** | Multi-venue owner / acquisition plans | Custom minimum + lower revshare band + portfolio reporting | Strategy call post-proof |

### Step 4 — Continuity

**Offer name:** Operator Continuity (Revenue Layer Maintenance + Optimization)

- **Billing:** same revshare structure ongoing (best alignment). Optional quarterly billing for lower churn / longer lookback.
- **Trigger:** Passed Install Month, continues operating through Trellis.
- **Value delivered:** Ongoing AI tuning, follow-up optimization, calendar rules, reporting, leak fixing.
- **Retention anchor:**
  - Monthly baseline vs current scorecard
  - Deposit consistency + low response time
  - Owner not bottleneck
  - Continuous "found money" (recovered ghosts, filled dead dates)

### Step 5 — Downsells

| Downsell | Trigger | Pricing | Win condition |
|---|---|---|---|
| **Systems Operator Plan** | Reject revshare / no marketing / cost reduction only | Fixed monthly minimum + optional smaller performance share | Stays active + centralized; no churn |
| **30-Day Pilot (Trial With Penalty)** | Said no to core | $0 if terms met; pay if not | Converts to core after pilot |
| **Maintenance Lite** | Seasonal / cash crunch / pausing marketing | Small fixed fee to keep system live + reporting, no growth work | Avoid cancellation; retain data + control |

## Money Movement Map

### Sales (pre-close)
- Classify stage by monthly booked revenue.
- Set baseline definition + measurement window.
- Lock required minimum package (Foundation DemandOS) unless disqualified.
- Present Trial With Penalty terms.

### Ops (Install Month)
- Stand up BookingOS: pipeline, AI response, follow-up, deposits.
- Verify tracking: every inquiry captured + every deposit tracked.
- Create "Done" checkpoints with timestamps.

### Finance (billing)
- Month 1: $0 if terms met; otherwise charge penalty / convert.
- Month 2+: calculate incremental above baseline; apply total take rate.
- Bill on longest practical cycle (monthly default; quarterly optional).

### Automations (triggers)
- "Roadmap booked" → send baseline form + data checklist.
- "Qualified" → send Trial With Penalty agreement + onboarding tasks.
- "Install complete" → schedule Day 30 review + upsell decision.
- "Utilization high, margin low" → offer Optimization upsell.
- "Cancel intent / failed payment" → present Pause or Systems Operator downsell.
