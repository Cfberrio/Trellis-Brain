## Operating Principle — Process > All
Process discipline is what makes the model transferable. For each core system: checklist + training + owner + quality standard + replacement plan.

## Leads System
- **Checklist:** missed-call text, answered-call Decision Packet, stop-on-reply, tagging
- **Training:** roleplay inbound availability calls + scripted handoff to SMS
- **Owner:** Lead Ops
- **Quality standard:** 95%+ of inbound captured into CRM thread
- **Replacement plan:** documented call scripts + recorded examples + QA rubric

## Sales System
- **Checklist:** confirm availability → ask Hourly/Daily → confirm rules fit → deposit link
- **Training:** objection reps (price, "think about it," partner approval)
- **Owner:** Booking closer (currently Sebastian per [[../05-Operations/SOPs/Sales-Trainee-Guide|Trainee Guide]])
- **Quality standard:** response time SLA + deposit conversion target
- **Replacement plan:** call library + objection playbook + shadowing

## Onboarding System
- **Checklist:** confirmation packet + rule acknowledgement + staffing scheduled + add-on deadline reminders
- **Training:** admin SOP + CRM workflow triggers
- **Owner:** Admin lead
- **Quality standard:** Pending → Confirmed within SLA; Confirmed → Pre-Event Ready within SLA
- **Replacement plan:** templated messages + checklist automation + escalation rules

## Delivery System (Day-of + Post-event)
- **Checklist:** pre-event setup + tech check + incident log + inspection + fee decision + review request
- **Training:** cleaning + tech + manager SOPs
- **Owner:** Ops manager
- **Quality standard:** inspection SLA met + incidents/fees documented consistently
- **Replacement plan:** standardized inspection checklist + photo requirements + training videos

## Cross-System Quality Bar
- Every system has an owner
- Every owner has a checklist
- Every checklist has a quality standard
- Every standard has a replacement plan

> If any of these 4 layers is missing, the system is not yet scalable.
